# План создания браузерного расширения "Deepfake Detector Pro"

## 1. Введение
Документ описывает план создания браузерного расширения для анализа изображений в документах на наличие дипфейков. Расширение будет следовать Manifest V3 и использовать современные практики веб-разработки.

## 2. Анализ требований
### 2.1. specification.md
- Расширение должно анализировать фото в документах.
- Определять, что фотография не сгенерирована нейросетью и не взята из интернета.
- Выдавать процент "реалистичности".
- Предупреждать, если лицо не уникально.

### 2.2. openapi.json
- API предоставляет эндпоинт `/analyze` для загрузки и анализа документа (PDF или изображение).
- Требует аутентификации (через Telegram или API-ключи).
- Возвращает задачу с ID и статусом, а затем результат анализа.
- Результат анализа включает информацию о лицах, изображениях и сводку.

## 3. Архитектура расширения (Manifest V3)
### 3.1. Компоненты
- **Фоновый сервис-воркер (Background Service Worker)**: 
  - Управляет жизненным циклом расширения.
  - Обрабатывает сообщения от popup и options страниц.
  - Хранит состояние аутентификации (токены) в `chrome.storage.session` или `chrome.storage.local`.
  - Может выполнять запросы к API от имени popup (чтобы избежать CORS issues в popup, так как popup имеет свою собственную origin).
  - Регистрирует обработчики для контекстного меню (если реализовано).
- **Popup**:
  - Отображается при клике на иконку расширения.
  - Предоставляет интерфейс для загрузки файла (перетаскивание или выбор через input).
  - Отправляет файл на анализ через фоновый сервис-воркер (или напрямую, если CORS позволяет, но лучше через фоновый для единой точки аутентификации).
  - Отображает результаты анализа (процент реалистичности, предупреждения).
  - Позволяет войти через Telegram или ввести API-ключ для аутентификации.
- **Options Страница**:
  - Позволяет настроить URL backend API (по умолчанию http://127.0.0.1:8000).
  - Управление API-ключами (просмотр, создание, удаление, ротация) - если пользователь предпочитает API-ключи вместо Telegram.
  - Настройки уведомлений и порогов срабатывания.
- **Content Scripts** (опционально, для будущих версий):
  - Добавление пункта контекстного меню при правом клике на изображение на веб-странице.
  - Отправка изображения на анализ через фоновый сервис-воркер.
  - Отображение результата во всплывающей подсказке или в новой вкладке.

### 3.2. Поток данных
1. Пользователь загружает файл в popup.
2. Popup отправляет сообщение фоновому сервис-воркеру с файлом и запросом на анализ.
3. Фоновый сервис-воркер проверяет наличие действительного токена доступа.
   - Если токен отсутствует или истек, пытается обновить его с помощью refresh токена.
   - Если обновление не удалось, запрашивает у пользователя повторную аутентификацию (через Telegram или ввод API-ключа).
4. После получения действительного токена, фоновый сервис-воркер отправляет файл на эндпоинт `/analyze` backend API.
5. Фоновый сервис-воркер получает ответ с ID задачи и периодически опрашивает эндпоинт для проверки статуса (или использует вебхуки, если API поддерживает, но по openapi.json видим только опрос).
6. По завершении анализа, фоновый сервис-воркер отправляет результат обратно в popup.
7. Popup обновляет интерфейс, показывая процент реалистичности и предупреждения.

### 3.3. Безопасность
- Минимизация прав в manifest: только необходимые разрешения (storage, активные вкладки для popup, возможно, контекстное меню).
- Все чувствительные данные (токены) хранятся в `chrome.storage.session` (удаляется при закрытии браузера) или `chrome.storage.local` с шифрованием (если требуется дополнительная безопасность).
- Запросы к backend API выполняются только на HTTPS (или на localhost для разработки).
- Валидация входных данных на стороне popup и фонового сервис-воркера (проверка типа файла, размера).
- Использование Content Security Policy (CSP) в manifest для ограничения загрузки ресурсов.

## 5. Стек технологий
- **Язык**: TypeScript
- **Фреймворк для UI**: React (с хуками) для popup и options страницы. Для простоты можно начать с Vanilla JS, но план предполагает React для масштабируемости.
- **Сборка**: Vite (быстрая сборка и горячая замена модулей) для разработки и production сборки.
- **Тестирование**: Jest и React Testing Library для unit и интеграционных тестов.
- **Линтинг и форматирование**: ESLint (с плагинами для React и TypeScript) и Prettier.
- **Управление состоянием в popup и options**: React useState и useContext (или Redux Toolkit, если состояние сложное).
- **Асинхронные операции**: async/await с использованием Fetch API или Axios (для удобства).

## 6. План реализации (поэтапно)
### Этап 1: Настройка проекта
- Инициализация репозитория в папке `extension`.
- Создание `package.json` с зависимостями (react, react-dom, typescript, @types/react, @types/chrome).
- Настройка Vite для сборки расширения (выходная папка `dist`).
- Настройка ESLint и Prettier.
- Создание базового manifest.json в папке `public`.

### Этап 2: Фоновый сервис-воркер
- Создание сервис-воркера в `src/background/index.ts`.
- Регистрация обработчика `chrome.action.onClicked` для открытия popup.
- Реализация механизма хранения и обновления токенов (доступа и обновления) в `chrome.storage.session`.
- Создание API клиента для запросов к backend (с автоматическим добавлением токена в заголовок).
- Реализация логики загрузки файла и отправки на анализ (с опросом статуса задачи).

### Этап 3: Popup (React)
- Создание React приложения в `src/popup/index.tsx`.
- Реализация интерфейса с зоной перетаскивания и кнопкой выбора файла.
- Интеграция с фоновым сервис-воркером через `chrome.runtime.sendMessage` и `chrome.runtime.onMessage`.
- Отображение состояния загрузки, результата и ошибок.
- Реализация входа через Telegram (используя Telegram Widget API) или ввода API-ключа.
- Сохранение выбранного метода аутентификации в состоянии popup и передача его в фоновый сервис-воркер.

### Этап 4: Options Страница
- Создание options страницы в `src/options/index.tsx`.
- Реализация формы для настройки backend URL.
- Реализация управления API-ключами (список, создание, удаление, ротация) через вызовы к backend API (требует аутентификации).
- Сохранение настроек в `chrome.storage.sync` или `chrome.storage.local`.

### Этап 5: Content Scripts (опционально)
- Регистрация content script в manifest для работы на определенных страницах или по контекстному меню.
- Реализация отправки выбранного изображения (через контекстное меню) на анализ через фоновый сервис-воркер.
- Отображение результата во всплывающей подсказке или в модальном окне.

### Этап 6: Тестирование
- Написание unit тестов для API клиента и утилит.
- Написание интеграционных тестов для фонового сервис-воркера (с мокованием chrome API и fetch).
- Тестирование React компонентов с использованием React Testing Library.
- Ручное тестирование в браузере Chrome/Edge для всех сценариев из specification.md.

### Этап 7: Обеспечение качества и безопасность
- Проверка соответствия Manifest V3 (валидация manifest).
- Аудит безопасности с использованием инструментов вроде SonarJS или ручной проверки.
- Проверка производительности с помощью Lighthouse (для popup и options страниц).
- Убедиться, что все запросы к backend выполняются через HTTPS (или localhost в разработке).

### Этап 8: Документация и подготовка к релизу
- Создание README.md с инструкциями по установке, настройке и разработке.
- Генерация финальной сборки (минифицированный код) в папку `dist`.
- Подготовка материалов для публикации в Chrome Web Store:
  - Создание иконок различных размеров.
  - Подготовка скриншотов popup и options страницы.
  - Написание описания расширения, выделения ключевых функций.
  - Создание политики конфиденциальности (если требуется).

## 7. Проверка соответствия исходным документам
Каждый этап реализации должен включать проверку соответствия:
- specification.md: функциональные требования (анализ фото в документах, вывод процента реалистичности, предупреждение о неуникальном лице).
- openapi.json: корректное взаимодействие с API endpoints (анализ, аутентификация, управление API-ключами), обработка ошибок и ответов.

Следуя этому плану, мы создадим современное, безопасное и удобное браузерное расширение, которое соответствует всем требованиям и готово к публикации.
